# Author Distinctions (warm)

> Author distinctions are stored here and in `extensions/`; `.claude/rules/distinctions.md` is the platform hot layer.
> This file: less frequent distinctions, loaded on trigger.

- **Development program ≠ Primary key for leadership selection** (peer-session 2026-05-31-12, pilot model, DP.M.241 §S1.5). The program (personal/role/integration/…) is a runtime attribute of the frontmatter render (which skeleton template to use, which program-overlay to attach) and is derived from pilot analysis. Primary key of analysis = pilot state from 7 sources (digital twin / personal_search / Honcho / LMS+club / Diagnostician / self-declaration / Lifework) + `current_request` priority 1.0. Test: "does the program filter the pilot's context, or is it assigned from the context?" Assigned → correct. Filters → anti-pattern "textbook instead of context" (DP.SC.164 §6). When `primary_program` and qualification do not match — `primary_program` wins.
- **Governance phase ≠ Operations phase in an umbrella** (peer-session 2026-05-30-40, WP-371). Umbrella projects do not perform governance work (contracts, forms, rules) — governance requires a separate work project with an owner. Operations work (metadata on existing content: markup, indexing, graph enrichment) CAN be contained as a direction phase inside an umbrella coordinator — without a separate child work project. Test: "is this a system form (governance) or metadata on a form (operations)?" Example: the `program × stage × domain` contract for the Tailor → WP-371 as a separate work project. Markup of universal guides by concept graph → phase F6 of WP-364 direction 2 (operations inside the Factory umbrella).
- **Gateway (pattern) ≠ Aisystant MCP (instance).** In external texts (consent, UI, README) = "Aisystant MCP".
- **MCP display identity ≠ machine identity.** Display: serverInfo.name, consent UI. Machine: CF Worker name, client_id, env vars. On rebrand — display only.
- **Terminal fail ≠ Transient fail** (scheduler.sh). In the retry loop: terminal → mark_done (1 TG); transient → retry.
- **Neon pooler masks FATAL** as transient (ConnectionDoesNotExistError). Diagnosis: retry via unpooled endpoint.
- **HTTP status check ≠ keyword check** (HD #51). CF Workers: HTTP 200 + 0 bytes = false-green on route loss. Keyword check is mandatory.
- **Single cursor ≠ Per-domain cursor** (WP-270). Single: failure of one Projection blocks all. Per-domain: N rows, isolated.
- **Smoke-test directory guard ≠ Path validation** (template-sync.sh). Guard detects ephemeral `/tmp/iwe-smoke-*` pattern + unsets; validation checks file existence after resolution. Both are required: guard = prevention, validation = defense-in-depth.
- **Universal guide ≠ Personal guide** (WP-300). Both are Projections of Pack PD (SoT). Universal: method for everyone, no RCS. Personal: Projection for a pilot via stage+bottleneck+domain. Do not rewrite one through the other.
- **Local Gateway (DP.IWE.005) ≠ Cloud Gateway (DP.IWE.003 / Aisystant MCP)** (WP-150 F6, 11 May). Local: in-process / Unix socket, single-user, multi-agent in VS Code, promise = tool routing + file lock. Cloud: HTTPS + OAuth Ory, multi-tenant, for external AI clients (claude.ai/ChatGPT), promise = knowledge delivery + access control. Describing both in one Pack document = drift within a month.
- **Peer Agent ≠ Planner/Executor** (WP-150 F7, 11 May). Peer (DP.ROLE.039): equals, coordination via explicit protocol (lock + peer-status + sequential commits), on disagreement → escalation to pilot. Planner/Executor (deprecated): hierarchy, one commands, the other executes. Test: if there is an "arbiter" from among the agents → not peer.
- **Protocol step numbering:** letter suffixes (3a/3b/3c) are unique within a single file, not within a single section. Inserting a new step → fractional format (3.5) if the letter is already used in another section of the same file.
- **Inventory ≠ Progress** (Throughput Accounting, Goldratt). An open PR, an unclosed work project, a draft in inbox = frozen capital, not progress. Test: "delivered to the user / physically complete — Throughput; still in progress — Inventory." Application: when evaluating "many active work projects" — this signals inflated WIP, not productivity (WP-313 F1).
- **AI user ≠ Developer of own agents** (WP-245 F30, 7 May). User: uses ready-made agents via chat/IDE, gets average results on typical tasks. Developer: writes DP.ROLE/DP.METHOD in Pack, engineers MCP tools, assembles Persona/Memory for their own work. Test: "do you formalize your own methods as a contract for a Role Performer?" The fork — a ceiling at the user level; moving to the developer level = a qualitative shift in caliber (stages 4–5 of the personal development program).
- **Self-development ≠ Work** (PD.D.142, 4 May). 4 simultaneous levels: Mastery (of developing oneself ≠ of work) / Culture / Methods (M001–M008 ≠ 14 elements) / Work projects (learning ≠ real). Transferability test: "if you change teams tomorrow — what stays with you, what stays in the environment?" Stays with me → self-development method. Stays in the environment → element of work culture.
- **Worldview ≠ Opinion** (PD.FORM.097, 4 May, WP-245 F16). Worldview = executable code (formalized rules, verifiable by recall/precision on real cases), not a "position." Test: can a mismatch be checked on a specific case? No → opinion, not worldview. The 4 transparent-box lenses are a way to read the canonical model.
- **Recorded time ≠ Invested time** (WP-310, 15 May). Recorded = all conscious time (work + learning). Invested = self-development only (slot_logged). Spent = recorded − invested (computed, not asked). The stage_evaluator reads invested time only.
- **Role object ≠ Role characteristic** (WP-300, 17 May). Object = what the Role looks at (problem for the Intellectual, task+product for the Professional). Characteristic = description of execution quality (quality of thinking — not an object, but a measure). Test: "does the Role look at X, or does X describe the Role?"
- **Agent Inbox (WP-324) ≠ Session Memory fault-profile (WP-316) ≠ Trace store (WP-295)** (17 May, clarified 29 May). Agent Inbox = transit queue of tasks + results. Session Memory = agent behavior patterns (iwe_memory.db). Trace store = decision archive for replay. Test: task/result vs. behavior patterns vs. decisions? Role = Functional Position; Role Performer = any LLM agent.
- **The name "Hermes" is NOT used in IWE for our Artifacts** (29 May 2026, peer-session 2026-05-29-21). Reserved for the external product **Hermes Agent (Nous Research, <https://hermes-agent.nousresearch.com/>)** — an LLM agent orchestrator with 8 memory providers (Honcho, OpenViking, Mem0, Hindsight, Holographic, RetainDB, ByteRover, Supermemory). Our roles are named explicitly: (a) **Session Memory Injector** — selects 2–3 agent fault patterns from iwe_memory.db and injects them at the start of Day Open; (b) **Profile Invalidation Signaler** (`diagnostician-watcher`, background mode DP.ROLE.042 §3.4) — monitors triggers `bh.inv +50%`, `cp_assessment.age ≥90d`, `bh.sys +2` and sends `learning.domain_event` to the Navigator/Tailor/Attestor. Umbrella: **"IWE Session Memory Roles"** (WP-316). Third meaning — **Hermes runtime** in DP.IWE.001 §5.2 — external product of Andrey's team based on Nous Research Hermes Agent (layer 1).
- **Unambiguous result_location ≠ Fallback chain** (WP-324 F1, 17 May). result_location = `repo+branch+path`, single source of truth; mismatch = `status: failed`. Fallback ("push to main, otherwise PR, otherwise branch"): creates navigation noise (07–10 analyses scattered across 4 branches + 1 PR + main). Test: "can the result end up in multiple places?" Yes → bad pattern. **Extension (WP-324 C-review, 17 May):** "routing_key + derived path via the Map" = temporal fallback of the same class, if override is allowed or the Map changed between assignment and execution. Legitimate normalization requires freeze-at-assignment (the Dispatcher materializes the path in the task at `pending→assigned`); without freeze — fail screening by Stability criterion.
- **Memory provider (Honcho-style) ≠ Digital Twin** (WP-316 F8, 17 May). Memory providers (Honcho, Mem0, Hindsight) produce **fuzzy inferences** from conversation/text (LLM black-box). Digital Twin (Memory.Derived, HD #27) — **deterministic aggregates** of activity_log per FORM.089 §6.1 rules (cp.rhy/wld/skl/iwe/int/agt), verifiable against a reference (VR.R.001). Substitution is not allowed: different axes and different audit level. Test: "can an inspector verify the value by a rule?" Yes → Digital Twin, no → memory provider. Honcho-style is appropriate as an **additional** proxy-metric layer from primary content (reflections, captures, conversations) → contribution with weight w_honcho for characteristics with a weak signal from activity (cp.wld, cp.agt, bh.awr). Via ArchGate with a PII blocker (B7.3).
- **Parliament model ≠ President model** ([systemsworld.club](https://systemsworld.club/t/kak-ustroit-uchyot-personalnyh-dannyh-v-ii-srede-parlament-vmesto-prezidenta/38159), 9 Apr; applied WP-73 agenda 18, 17 May). President: one agent with full access to all user data domains. Parliament: triad **Accounting / Access / Audit** = N domain agents (each with its own zone of responsibility) + 1 coordinator (routes, does not store raw data) + 1 verifier (isolated, read-only). Architectural guarantee, not a recommendation — access denial at the platform level, not the prompt level. Test: "can a single agent independently read data outside its own domain?" Yes → President, no → Parliament. Applied to agent separation in the Agent Workshop Platform.
- **Pack ≠ Development program** (WP-334+WP-335, 18 May). A Pack describes a **field/domain** (Ontology, concepts, Roles, promises) — for example, PACK-systems-art describes the "systems art" domain. A development program describes a **course of development for a specific Role** in that field — for example, the Enlightenment Development Program describes the development of the Enlightener role, drawing on PACK-systems-art + PACK-personal + PACK-\<domain\>. Test: "is this a description of a Knowledge Domain or a plan for a person's development within it?" Do not conflate when naming: Pack = domain noun (`art`, `personal`, `MIM`), Program = function/activity (enlightenment, personal, work).
- **Development Controller ≠ Orchestrator ≠ Navigator ≠ Guide** (WP-326/343/346, 20 May, DP.D.076). **4 closely related roles in the pilot support domain**, different pace layers and channels. Controller (R46) — pull-sensor, 3× per day, scans and compares marker vs. fact, emits a signal. Orchestrator (R22) — parent coordinator between N Controllers and operational roles. Navigator (MIM.R.007) — motivational channel, push-dialog on trigger (3+ days of silence + history), does not scan. Guide (R13) — reactive FSM in the bot, milliseconds, executes the "update buttons" command. Control profiles (Development/Style/Qualification/Onboarding/Domain) — a parameter of R46, not separate roles. Test: "decision about mode priority?" → R22; "check marker against fact?" → R46; "dialog with a specific stuck user?" → Navigator; "switch FSM state in the bot?" → R13.
- **Points (gamification) ≠ Bonuses (loyalty) ≠ Stage (qualification)** (WP-327, DP.D.050, 20 May). Three accounting systems for one activity. **Points** = earned_total (NEVER decrease) → leaderboard, history; DP.ROLE.034. **Bonuses** = `min(points, Σ(active_days_at_qual_i × daily_cap_i))` adjusted for qualification changes → discount on payment, spent; DP.ROLE.051 burn. **Stage** = cp-profile FORM.089 (13 cross-sections + 7 bh) → determines daily_cap. TODO: `earned_total` column in `point_balances` (~2h, after WP-327 Stage 4). Test: "does it never decrease?" → points. "Spent on payment, capped by days history?" → bonuses. "Determines Mastery?" → stage.
- **Distribution-bundle ≠ Distribution-coupling** (WP-337, 22 May). Linux distribution (Ubuntu) = bundle of coordinated components + tight coupling to the kernel (Ubuntu does not run on a BSD kernel). IWE = portable runtime + Pack + host adapters via DP.IWE.011 — bundle exists, coupling to a single LLM kernel does not. Analogy: closer to JVM (portable runtime) + POSIX (host contract) than to Ubuntu. Test: "does it work when the kernel is replaced?" Yes → bundle meaning. No → coupling meaning. In public-facing text: specify which meaning is intended.
- **LLM kernel (paid) ≠ Linux kernel (open-source)** (WP-337, 22 May). In a Linux distribution the kernel is free — the Red Hat model "content is free, infrastructure is paid" works. In IWE the kernel is the LLM (Claude, GPT) — an external paid resource; every call = operating cost. Consequence: there is no pure free tier; T1 is implemented via (a) LLM quota, (b) BYOK, (c) demo. Application: when calculating freemium economics, include LLM COGS in every ARPU; do not promise "free full access" in a trial.
- **Control role ≠ Operational role** (DP.D.080, WP-224 F4, 22 May). Control = observes + reports + read-only access to audited Artifacts + has an explicit recipient (R23–R26). Operational = changes the state of the System of Interest + idempotent + has no external recipient (R8, R11). Test 1: "did the audited Artifacts change?" No → control (output channel/report does not count). Test 2: "is there an explicit report recipient?" Yes → control. Conflation: an auditor who edits what they audit loses independence (2 defects); an operational role writing a report instead of acting = WIP/Inventory. The separation is logical, not physical: one agent can perform both roles in different sessions while maintaining invariants.
- **Router ≠ Dispatcher (DP.ROLE.045) ≠ Artifactor (Framer) ≠ Decomposer** (WP-350, 25 May). **4 roles in the IWE task execution system**, different functions. Router (DP.ROLE.059 R30) — single entry point: routing tag from WP Gate or Artifactor → lookup in executor-catalog.yaml → single executor. Dispatcher (DP.ROLE.045) — manages the `inbox/agent/tasks/` queue, launches via CCR/systemd. Artifactor-Framer (DP.ROLE.058) — no routing tag → structured request + tag → returns to Router (does not call executor directly). Decomposer (DP.ROLE.053, F5 WP-350) — ready work project ≥3h → stages with physical Artifacts. Test: "route an incoming request?" → Router; "launch a task from inbox?" → Dispatcher; "frame a work project from raw input?" → Artifactor; "break a work project into stages?" → Decomposer.
- **Workspace peer coordination ≠ Conversational peer session** (WP-337-Z-F1, 22 May, DP.D.084). Workspace: different files, parallel, coordination via Local Gateway lock + peer-status (DP.SC.034/035). Conversational: one task, turn-taking, coordination via reply log + `ESCALATE_TO_USER` marker (DP.SC.154). Within conversational — two positions of one role DP.ROLE.039: writer (has write access, assembles `report.md`) and Peer partner (right to disagree and escalate, does not write to workspace). Test: "do they share different files or discuss one task (one report)?" Mixing modes produces either false lock conflicts on one task or unilateral overwriting.
- **Agent ≠ Role** (WP-350/WP-336, 25 May). Agent = executing system: {LLM, Tools, Prompt, Persona (Memory), Context} — a specialization of "System" from "System-in-role ≠ Role" (FPF A.2.1, above). Role = Functional Position: what to do, authority, domain, I/O. Same notation: `agent#role:context`. Test: "remove the agent — does the Role remain?" Yes → Role ≠ agent. Naming exception: a specialized agent (one agent = one role, domain is bounded) MAY be named after the role — then agent name = role name (session-memory-injector, overnight-reviewer). A universal agent (Claude Code, Kimi Code) plays different roles → its name ≠ role name. Detail → [agent-architecture-framework.md](../../memory/agent-architecture-framework.md).
- **Universal agent ≠ Specialized agent** (WP-350/WP-336, 25 May). Universal: can play many roles (Claude Code, Kimi Code), broad context, high trust. Specialized: one agent — one role, binding is architectural; LLM kernel is replaceable, but the role is not. Test: "can the agent take on a different role?" Yes → universal. No → specialized. Examples of specialized: session-memory-injector, overnight-reviewer, overnight-tester.
- **Platform agent catalog ≠ IWE executor-catalog** (WP-336 vs WP-350 F8, 25 May). Platform catalog (WP-336, Andrey): cloud agents of Aisystant, Parliament model, HTTPS+OAuth, multi-tenant. IWE executor-catalog (WP-350 F8, file `executor-catalog.yaml`): executor agents in VS Code, Local Gateway, single-user. Two levels, two consumers — do not mix when designing.
- **Session request ≠ Task (Agent Inbox)** (WP-358 peer-session, 26 May). Task (DP.SC.135): deferred request with `due/template/acceptance/result_location`, SLA ≤1h, batch processing. Session request: real-time initiation of a Claude session from outside (Telegram), no `due`, no template, no acceptance — the pilot wants "open a session here and now." Test: "is there a `due` and `acceptance`, or is this a live dialog?" Diff in SLA, failure modes, contract. Forcing a session into `inbox/agent/tasks/` = breach of the WP-324 contract. Solution: separate folder `inbox/agent/sessions/`, one dispatcher with `--mode session`.
- **Session: light ≠ heavy** (DP.SC.162, WP-358 peer-session, 27 May). light = expected response ≤200 tokens, sync SLA P95≤45s. heavy = response >200 tokens or indeterminate duration, async mode with progress notifications every 15s. Test: "will the response fit in 200 tokens within 45s?" Yes → light, sync. No → heavy, async. Apply when designing SLA for DP.SC.162.
- **Turn ≠ Session** (DP.SC.162 v2, WP-358, 27 May). Session = the full dialog from opening to `/close` (1..N turns), identified by `session_id`, lives in `SESSION-<id>.md` + `SESSION-<id>-thread.md`. Turn = one request+response pair, identified by `(session_id, turn_n)`, tracked as a separate Domain Event. Timeout for the session (60 min of silence) and for a turn (15 min hard cut-off) — separate timers.
- **Google Calendar "IWE Platform Ops" ≠ process-catalog/ledger ≠ inbox/reminder-*.md ≠ personal Calendar** (DP.D.102, peer-session 2026-05-28-01). Four semantic event channels in IWE. One-shot work project deadlines → Calendar IWE Platform Ops (with mobile push). Rhythmic processes (Day Open, marathon) → process-catalog→ledger→watchdog (automation). Discrete reminders without automation → inbox/reminder-*.md. Personal → personal Calendar. Recording a work project deadline in date-ledger.yaml = OwnerIntegrity violation (ledger is derived, gets overwritten).
- **DS Creator (Loop A) ≠ Pack Creator (Loop B)** (SPF example, systemsworld.club/t/organizacziya-kastomizaczii…, 2026-05-31). Loop A: delivering value to a specific consumer (adaptation, integration for a client). Loop B: extracting repeatable patterns from local work → scalable components (Pack). Mixing loops = the company appears scalable, internally — undirected consulting. Critical rule: "local delta does not go into core roadmap without a route decision." Test: "whose responsibility — deliver to this client, or generalize for everyone?"
- **HOT horizon: hard limit 150 lines** (WP-7 NR1.2, 31 May 2026). Memory-exocortex HOT limit = 150 lines per file. Exceeding this = constant manual rewriting (Claude Code: 1000-line file is above the 1000-line threshold). Script `memory-bleed.sh` checks `wc -l`; if >150 → flag. Split: header block (frontmatter + aggregates) + body block (linear list); body can be extracted to a separate `memory/<topic>-items.md` with `horizon: warm`. Test: "is the HOT file >150 lines?" → split or demote.
- **horizon warm→cold: 14-day cutoff** (WP-7 NR1.2, 31 May 2026). Warm files older than 14 days (mtime) are automatically demoted to cold via `sed -i '' 's/horizon: warm/horizon: cold/'` (macOS). Contrast: hot = active session, warm = recent (<14d), cold = archive. Script `memory-bleed.sh` lists demotion candidates. Test: "is the file warm, age>14d?" → demote to cold.
- **Internal alert (failure) ≠ External heartbeat (dead-man's switch)** (INCIDENT-2026-06-03). Internal (`if: failure()` inside the workflow itself) catches "started and crashed." External heartbeat (BetterStack waits for a ping, alerts on silence) catches "did not start at all" — disabled schedule, exhausted limit, Actions turned off. Analogy: the guard inside the building is asleep if the building itself is switched off. Test: "if the process does not start, will anyone know?" — only the external heartbeat. A billing-critical pipeline requires both layers. The 12 May incident was of the "did not start" class (sync was failing on authentication — 3 weeks of silence showed: an internal alert is not enough).
