# Агентная архитектура IWE: LLM / Агент / Роль

> WP-350/WP-336, 25 мая 2026. Краткие различения → [[distinctions.md]] (AUTHOR-ONLY).

## Три слоя

| Слой | Что это | Примеры |
|------|---------|---------|
| **LLM** | Языковая модель — «ядро» рассуждений. Не агент сам по себе. | Claude (Haiku/Sonnet/Opus), Nous Hermes, GPT-4, Mistral |
| **Агент** | Система = {LLM, Инструменты, Промпт, Персона (Память), Контекст}. Специализация «Системы» в нотации FPF A.2.1. | Claude Code, Kimi Code, session-memory-injector, overnight-reviewer |
| **Агент-в-роли** | Агент исполняет конкретную роль в конкретном контексте. Роль = функциональное место (что делать, полномочия, домен, I/O). Нотация: `агент#роль:контекст` | `claude-code#стратег:IWE`, `session-memory-injector#session-memory-injector:day-open` |

> **Связь с HD #27 (DP.D.052):** Персона — постоянная часть (кто агент, его профиль), Память — накопленный опыт, Контекст — текущая сессия. Все три входят в состав агента.

**Именование специализированного агента:** если агент исполняет одну роль и ограничен её доменом → имя агента = имя роли (`session-memory-injector`, `overnight-reviewer`). Универсальный агент (Claude Code, Kimi Code) играет разные роли → имя не совпадает с именем роли.

## Два типа агентов

### Универсальный агент
- Может играть **много ролей** — назначение ситуативное
- Широкий контекст, высокий уровень доверия
- Не привязан к одному домену
- Примеры: **Claude Code** (Sonnet/Opus), **Kimi Code** (длинный контекст)

### Специализированный агент
- **Один агент = одна роль** (привязка архитектурная, не ситуативная)
- LLM-ядро внутри **заменяемо** (Haiku → Hermes → GPT → …)
- Домен ограничен, полномочия узкие

| Агент | Роль | LLM сейчас | Домен |
|-------|------|------------|-------|
| session-memory-injector | Session Memory Injector (TBD DP.ROLE.NNN) | Claude Haiku | fault-profile памяти агента |
| overnight-reviewer | Code Reviewer | Claude Sonnet | качество кода |
| overnight-tester | QA Тестировщик | Claude Sonnet | тесты / smoke |
| overnight-critic | Критик | Claude Sonnet | верификация артефактов |
| idea-scout | Исследователь идей | Claude Sonnet | поиск источников/идей |

## Типы ролей (DP.D.080)

| Тип | Что делает | Примеры |
|-----|-----------|---------|
| **Операционная** | Изменяет состояние системы; идемпотентна; нет внешнего получателя | Стратег R1, Декомпозитор |
| **Контрольная** | Наблюдает + отчёт; read-only к аудитуемым артефактам; есть явный получатель | Верификатор R23-R26, Аудитор R24 |
| **Координационная** | Маршрутизирует/диспетчеризирует; знает имена, не данные | Маршрутизатор R30 (DP.ROLE.059), Диспетчер (DP.ROLE.045), Оркестратор R22 |

## Два каталога

### Платформенный каталог агентов (WP-336, Андрей)
- **Уровень:** Aisystant-платформа (облако)
- **Инфраструктура:** HTTPS + OAuth Ory, Cloud Gateway, Парламент-модель
- **Потребители:** мульти-тенант, пилоты платформы
- **Статус:** проектирование отдельной инициативой (WP-336)
- Включает: платформенные роли — Диагност R28, Навигатор R27, Портной (Tailor), Аттестатор, Верификаторы R23-R26, Геймификатор R34, Оркестратор R22 и др.

### IWE executor-catalog (WP-350 Ф8)
- **Уровень:** IWE в VS Code (пилот-разработчик)
- **Инфраструктура:** Local Gateway (DP.IWE.005), AGENTS.md, file-lock
- **Потребители:** Маршрутизатор DP.ROLE.059, пилот через `/route-task`
- **Статус:** ещё не создан → реализуется в Ф8 WP-350
- Файл: `executor-catalog.yaml` (поле `can_play_roles` у каждого агента)
- Включает: IWE-агенты + скрипты + MCP-инструменты

## Подключение нового агента (Nous Hermes, другой LLM)

1. Выбрать инфраструктуру запуска: Ollama (local) / Together AI API / Groq API
2. Написать adapter-скрипт по образцу `kimi-peer-adapter.sh` — headless вызов + AGENTS.md
3. Зарегистрировать в `executor-catalog.yaml` (Ф8 WP-350)
4. Агент должен поддерживать IWE-протокол: читать AGENTS.md, коммитить с атрибуцией, уважать file-lock

**Важно:** Hermes model (Nous Research) = LLM-ядро, не агент; OpenClaw = отдельная платформа (247k stars), не инструмент внутри IWE.

## Ядро IWE + агенты-интерфейсы: общее vs своё

Все агенты (Claude, Kimi, Hermes, агент пользователя) подключаются к одному ядру IWE (Aisystant MCP) и берут из него СУТЬ — ориентацию, знание, контекст пилота, авторитетную память. Один вопрос через любой интерфейс → один по сути ответ (см. «суть ≠ интерфейс», DP.D.156).

| Что | Где живёт | Общее или своё |
|-----|-----------|----------------|
| Ориентация, знание, авторитетные факты | Ядро (Aisystant MCP) | ОБЩЕЕ для всех агентов |
| Контекст текущего диалога | Локально у каждого агента | СВОЁ (норма) |
| Инструменты, манера | У каждого агента | СВОЁ |
| Встроенная автономная память (диалоги, навыки, self-evolution) | Только у Hermes (его рантайм) | СВОЁ — но не источник истины |

**Граница (DP.D.156):** что ядро воспроизводит без агента = интерфейс; что закреплено только агентом = нарушение. Факты из встроенной памяти Hermes перетекают в ядро через capture с апрувом — Hermes предлагает, утверждает экстрактор/пилот.

**Подключение агента пользователя:** ядро assistant-agnostic («Платформа ≠ IWE-помощник») — любой агент через MCP получает доступ к сути в рамках прав и тира пользователя.
