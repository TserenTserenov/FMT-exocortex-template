# Диспетчер: Сессия стратегирования (weekly)

> **Роли:** Плановик ведёт недельный отбор и бюджет; Стратег подключается при пересмотре направления; человек утверждает решения · **Частота:** еженедельно (Пн) · **Длительность:** ~15–20 мин
>
> Это **короткий вариант** для еженедельного ритма. Полный вариант (monthly) — `strategy-session-monthly.md`.

Сессию проводит личный Штаб стратегирования в короткой конфигурации. Плановик и Стратег здесь названия назначений, а не две дополнительные системы рядом с человеком. Состоявшаяся сессия — эпизод работы; её результат записывается в план недели и связанные записи. Обзор входов и выходов полной сессии дан в `.claude/skills/strategy-session/SKILL.md`; этот маршрут использует только перечисленные ниже шаги.

## Стиль общения с пилотом

Все ответы в сессии — **режим «на пальцах»** (S-37, A1-A11):
- Только русский язык. Английский термин — только в скобках после русского описания.
- Технические метки типа «gate: skip», «exit 0», имена файлов — **не писать в чат**. При пропуске шага (gate: skip-if-empty) — сообщи пилоту коротко («Нерегулярных блоков нет»), затем **СТОП — жди ответа, не переходить молча**.
- Пути к файлам — только в скобках после русского глагола, никогда подлежащим.
- Объяснять через «что это значит для плана», не через «что сделал Клод».

## Предусловие

Черновик WeekPlan (`status: draft`) уже создан сценарием `session-prep` (Пн 04:00). Если черновика нет — сообщи пользователю и предложи запустить `session-prep`.

## Resume — обнаружение незавершённой сессии

**До чтения шага 00** — проверить `current/WeekPlan W*.md` на наличие раздела `## Итоги Strategy Session` с незакрытыми пунктами (⏳):

Если найден WeekPlan с ⏳ в разделе сессии:
- Сообщи пилоту: «Найдена незавершённая сессия W{N}. Последний выполненный шаг: [найди последний ✅]. Возобновить с шага [N+1] или начать заново?»
- **СТОП — жди ответа пилота.**
- Возобновить → читать файл шага N+1. Начать заново → к обзору сессии ниже.

Если незавершённой нет → сразу к обзору сессии ниже.

## Обзор сессии (обязательный гейт, один раз, перед шагом 0)

Выполняется в обоих случаях свежего старта — Resume не нашёл незавершённую сессию, или пилот выбрал «начать заново». Прежде чем читать файл шага 0 (`00-open.md`), вывести пилоту одним сообщением, человеческим языком (без путей, без технических меток шлюза), список этапов именно этого (короткого) варианта сессии из таблицы «Последовательность шагов» ниже — название каждого этапа одной строкой. Затем **СТОП — жди ответа пилота**, и только после него переходить к шагу 0.

## Инструкция для Claude (execution semantics)

> **БЛОКИРУЮЩЕЕ — шаг за шагом.** Нарушение = потеря смысла сессии: пилот не внёс свои данные, решения приняты без него.

**Правило одного шага:**
1. Прочитать файл ТЕКУЩЕГО шага.
2. Объявить пилоту одной строкой: название шага + какие данные будут использованы (поле «Вход» из таблицы ВДВ этого шага, человеческим языком).
3. Выполнить шаг, вывести результат пилоту.
4. **СТОП. Ждать следующего сообщения пилота.**
5. Только после ответа пилота — читать файл СЛЕДУЮЩЕГО шага.

**ЗАПРЕЩЕНО:**
- Читать `strategy-session-weekly/steps/*` через glob или несколько файлов за один ход.
- Переходить к следующему шагу без ответа пилота (даже если gate = `auto`).
- Объединять несколько шагов в один ответ.

**РАЗРЕШЕНО:** Read только файл шага, явно указанного на текущей позиции последовательности.

**После compaction / восстановления контекста:** правило действует без исключений. История того, что было сделано до compaction, не отменяет требование ждать пилота на каждом шаге.

## Что считать «срочным» в сессии стратегирования (модель ТВС)

> Различение [[Текущее ≠ Важное ≠ Срочное (ТВС)]] + [[Дедлайн ≠ Срочность]]. ТВС = Текущее · Важное · Срочное.

Сессия стратегирования — это место для **важного** (поднятие нормы), а не для срочного. По умолчанию в стратегической сессии **почти ничто не срочное**:

- **Срочное** = только физическая угроза остановки конвейера (прод/биллинг упал, блокирует других агентов/пользователей, потеря данных, security-critical). Настоящее срочное НЕ ждёт сессии — оно прерывает и чинится немедленно.
- НЕ срочное (= важное или текущее, даже если ощущается «горящим»): приближающийся дедлайн, сильная неудовлетворённость / высокая мотивация решать, «пилот хочет добавить РП», накопившаяся текучка. Дедлайн на важном остаётся важным.

Поэтому при оценке «нужен ли пересмотр состава РП» НЕ повышай элемент до срочного по дедлайну или по силе НЭП. Эскалация в monthly = сигнал пересмотра приоритетов важного, не «пожар».

## Weekly-stop gate (операционный критерий)

После шага 04 оцени:
> Требуется ли пересмотр состава РП текущей недели (убрать или добавить хотя бы один РП)?

- **Да** → сообщи пилоту:
  > «Обнаружен сигнал, требующий пересмотра РП текущей недели. Предлагаю перейти к полной сессии (`strategy-session-monthly.md`) для стратегической сверки.»
  - Если пилот согласен → заверши weekly, предложи monthly
  - Если пилот отказывается → зафиксируй риск в WeekPlan («пилот отказался от monthly при пересмотре РП») и продолжай
- **Нет** → продолжай к 06a

## Jump-обработка

В weekly-режиме jump-handler не используется. Критический сигнал (неудовлетворённость, прозвучавшая в разговоре, или расхождение стратегии из шага 04) обрабатывается weekly-stop gate.

## Проверка результата перед сессией (РП518 Ф17, решение пилота 19.10.2026)

Если перед сессией стратегирования нужна независимая проверка материала (например, кандидатов для шага плана) — эта проверка **не ведётся как часть этого пошагового ритуала** и не подменяет правило «один шаг, стоп, жди пилота» выше. Она идёт отдельно, до начала этой процедуры: либо диалогом с другим агентом (пир-сессия, Codex/Kimi), либо разбором силами одного агента (например, холодное ревью субагентом) — в обоих случаях задача проверяющего — посмотреть, что сделал первый агент, не согласиться с ним автоматически. Результат (отчёт или вывод проверки) становится одним из источников входных данных конкретного шага. При объявлении шага (см. «Правило одного шага», п.2) — если для этого шага есть релевантный результат такой проверки, назвать его явно как часть «Вход».
