# Step 08: Утверждение и синхронизация

## ВДВ

| | |
|---|---|
| **Вход** | WeekPlan draft, обновлённые Strategy.md, Dissatisfactions.md |
| **Действие** | Пилот подтверждает план → синхронизировать все артефакты |
| **Выход** | Утверждённый WeekPlan (`status: confirmed`), карточки выбранных РП, согласованные WP-REGISTRY, active-wp и MEMORY |

## Инструкция для Claude

1. **Утверждение:**
   - Пилот подтверждает конкретный план и список новых РП. До завершения регистрации и проверки ниже сохраняй `status: draft`.
   - **Проверка WeekPlan перед утверждением (ОБЯЗАТЕЛЬНО, WP-484 Ф47).**
     Базовый путь — ручной (штатный для чистой установки): сам проверь, что
     в WeekPlan у каждого РП проставлен цвет режима ТВС, сформулирована ТОС
     недели и есть явный список «не берём». Чего-то не хватает — разбери с
     пилотом, поправь и перепроверь. Опциональный ускоритель — только если
     установлен: при `[ -f "$IWE_SCRIPTS/strategy-session-checks-runner.sh" ]`
     запусти `bash "$IWE_SCRIPTS/strategy-session-checks-runner.sh" "<путь к WeekPlan>"`,
     красный результат блокирует переход к `status: confirmed`. Скрипт в
     поставку шаблона не входит (issue #409) — его отсутствие не блокирует:
     сообщи пилоту «машинная проверка WeekPlan недоступна на этой установке,
     проверяю вручную» и продолжи ручным путём.
   - **Регистрация новых РП (обязательно и для weekly, и для monthly):** выполни раздел «Регистрация РП перед утверждением» в `.claude/skills/strategy-session/SKILL.md`. Прочитай его целиком: проверка повтора → `/wp-new` в проверенном `GOV_WT` → карточка и строка реестра → проверка строки плана. Carry-over не регистрируй повторно. Источник и критерий готовности сохрани в карточке, чтобы они не исчезли вместе с архивом недели.
   - Ошибка или пропущенная запись — остановись, оставь `draft`; не переходи к следующим РП, публикации или очистке входящих. Проверь фактические файлы и сообщи, что осталось восстановить.

2. **Синхронизация (ОБЯЗАТЕЛЬНО):**
   - **MEMORY.md** → секция «РП текущей недели» по проверенному плану, включая новые `pending`. Путь, ручной способ и условия применения `memory-active-wp-update.sh` заданы в общем разделе регистрации. Успех скрипта не заменяет проверку номеров и названий.
   - **Strategy.md** — если добавлена работа, не отражённая в стратегии
   - **MAPSTRATEGIC.md** — если элемент из MAPSTRATEGIC взят в работу → `in-progress`; если фаза завершена → `done`
   - **Итоговая проверка:** для каждого выбранного РП есть карточка, ровно одна строка WP-REGISTRY и WeekPlan с тем же номером; обновлены active-wp и MEMORY. Только после этого смени `status: draft` → `status: confirmed` в WeekPlan.
   - **Очисти** из `fleeting-notes.md` заметки, по которым пилот уже принял решение (помеченные `✅предложено` без решения не трогай; процедура — «Очистка заметок» в `note-review.md`), и обработанные файлы из `inbox/`

3. **Запись сессии (ОБЯЗАТЕЛЬНО):** по ней диспетчер `strategy-session` узнаёт, была ли в этом месяце сессия стратегирования. Выполни пункты 2–3 расширения `extensions/protocol-close.after.session-record.md` сейчас: запись с `session_type: strategy` и `session_variant: weekly|monthly` по фактическому варианту. Запись этой сессии уже есть (например, создана при открытии сессии) — дополни её этими полями, вторую не создавай; закрытие сессии потом дополнит ту же запись.

4. **Commit:**
   - Закоммить изменения в governance-репо и затронутые репо

5. **Результат:**
   - Утверждённый WeekPlan W{N} (`status: confirmed`)
   - Карточки новых РП, согласованные WP-REGISTRY и active-wp
   - Обновлённые Strategy.md, MEMORY.md, MAPSTRATEGIC.md
   - Очищенный inbox
   - Запись сессии с `session_type: strategy`
