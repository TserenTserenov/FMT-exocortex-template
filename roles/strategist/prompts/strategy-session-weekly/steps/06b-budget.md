# Step 06b: Plan — Budget + TOC

## IPO

| | |
|---|---|
| **Input** | Candidate pool with priorities (step 06a) |
| **Action** | Allocate budget, define the week's TOC, record "what we are NOT taking" |
| **Output** | Approved budget, week's TOC, explicit "not taking" list |

## Instructions for Claude

1. **Budget fit + Time-boxing** — pilot adjusts:
   - Sum of budgets ≤ available hours (overage ≤10%)
   - Each Work Product has a hard cap: ≤4h small, 4–15h large, open-ended are prohibited

2. **Week's TOC** — pilot approves ONE constraint whose removal unlocks the greatest throughput. Record it in the WeekPlan header.

3. **Explicit "not taking" list:**
   - Record an explicit list of "What we are NOT taking this week and why"
   - This prevents implicit carry-over
   - **Each item must have a review deadline or trigger event** (the date of the next Session where the decision must return to the agenda, or a specific trigger). An item without a review deadline or trigger is not considered closed — at the next auto-pool collection it returns by default and must not disappear silently

4. **Question for pilot:**
   > "Continue to finalization / adjust / skip?"
