# Step 05a: Калибр — подсчёт

## ВДВ

| | |
|---|---|
| **Вход** | `Caliber-artifacts-tracker.md` и документы папки Lifework (где она — п.1), `docs/Dissatisfactions.md` |
| **Действие** | AI-вычисления: V_scope, A_scope, D_scope, качественный статус, проверка готовности |
| **Выход** | Измерения + рекомендация для шага 05b |

## Инструкция для Claude

> Метод: `PD.METHOD.018` § Механизм рекомендации Стратегом. Три поля и запрет арифметики — `PD.FORM.091 §6.1`.
> **Согласие:** перед чтением метрик ЦД — сверить согласие, см. [../appendix/consent-check.md](../appendix/consent-check.md). При `denied`/`null` — degraded (калибр на самооценке, без записи).

1. **Найди папку Lifework и трекер — не создавай их.** Папка по умолчанию — `$GOV_WT/Lifework/`. Если там нет `Caliber-artifacts-tracker.md`, ищи этот файл по рабочему пространству: `find {{WORKSPACE_DIR}} -maxdepth 3 -name Caliber-artifacts-tracker.md -not -path '*/templates/*' -not -path '*/.worktrees/*' -not -path '*/.iwe-runtime/*'` (документы Lifework могут жить вне репозитория стратегии). Найден один — его папка и есть папка Lifework для всего этапа «Калибр» (05a–05c), назови её пилоту при объявлении этапа. Найдено несколько — спроси пилота, какой действующий, и не продолжай до ответа. **Не найден ни один — трекер не создавай** (пустой трекер рядом с настоящим, лежащим в другом месте, — дубль, который перехватит запись): скажи пилоту, что трекера нет и где лежит заготовка (`templates/strategy-skeleton/Lifework/Caliber-artifacts-tracker.md`), и проведи этап на самооценке без записи (как при отказе в согласии).

2. **Классифицируй видение → V_scope.** Для каждого УСТОЙЧИВОГО (повторяющегося, не случайной реплики) НЭП определи категорию по проверочным вопросам `PD.FORM.091 §6.1` (аудитория + ответственность; системный уровень FORM.027 — опора, не замена):

   | Категория FORM.090 | Проверочный вопрос |
   |---|---|
   | 1. Я | Изменение относится к самому человеку и его способу действия? |
   | 2. Ближний круг | Изменение относится к длительным близким отношениям? |
   | 3. Дальний круг | Изменение относится к команде, проекту, заказчикам или профессиональному кругу? |
   | 4. Сообщество | Изменение относится к устойчивому сообществу или направлению? |
   | 5. Общество | Изменение относится к общественному институту, культуре или стране? |
   | 6. Человечество и поколения | Изменение относится к человечеству или будущим поколениям? |

   V_scope = наивысшая достигнутая категория. Системный уровень FORM.027 9-10 сам по себе НЕ даёт V_scope=6 — нужен явный объект изменения в человечестве/поколениях. Нет устойчивого НЭП, который классифицируется хоть по одной строке → `V_scope = unconfirmed`. Один НЭП одновременно подходит под несколько строк → статус `ambiguous`, уточнить диагностическим диалогом, не гадать.

3. **Подтверди действие → A_scope:**
   - Max категория охвата (`PD.FORM.090`) с наблюдаемым произведённым изменением или принятой ответственностью: завершённые проекты, решения, внешние результаты, подтверждение Диагноста
   - Lifework-документ НЕ обязателен для этой оценки — читай из папки Lifework из п.1, но его отсутствие не понижает A_scope
   - Подтверждённых действий ещё нет → `A_scope = unconfirmed` (не «ноль»: числовой нулевой уровень не вводится). Нет документа совсем → это одновременно `D_scope = none`; первый объект работы — безопасный обратимый личный проект уровня 1 и наблюдаемый след, не документ (`PD.METHOD.018` § Новый участник без документа)

4. **Проведи аудит документации → D_scope:**
   - Наивысшая категория охвата со зрелым Lifework-документом — читай из папки Lifework из п.1; зрелость — по локальным правилам `PD.METHOD.018` § Условия подъёма (срок разный по переходу: ≥6 мес для 1→2 и 2→3, ≥1 года для 3→4 и 4→5, ≥3 лет для 5→6 — не единый срок для всех уровней)
   - Нет документов → `D_scope = none`
   - Проверь полноту нижних инвариантов (`PD.FORM.090 §6`): все уровни 1..D_scope присутствуют?
   - Поломки внизу → рекомендация «догнать вниз», STOP здесь (поломка наверху = обрыв снизу, приоритетнее подъёма)

5. **Сопоставь V_scope и A_scope на одной шкале охвата → качественный статус** (`PD.FORM.091 §6.1`, порядковое сравнение внутри одной шкалы, НЕ арифметика):
   - V_scope = A_scope → `aligned`
   - V_scope на одну категорию выше A_scope → `adjacent_frontier`
   - V_scope на две и более категории выше A_scope → `vision_ahead`
   - A_scope выше V_scope → `action_ahead`
   - V_scope или A_scope = unconfirmed → статус `unconfirmed`
   - Сама категория V_scope или A_scope неоднозначна (шаг 2) → статус `ambiguous`

6. **Проверь локальную готовность к следующему документу** (`PD.METHOD.018` § Условия подъёма + § Локальный gate документа):
   - Предыдущий Lifework-документ прошёл свой тестовый период ПО ТАБЛИЦЕ «Условия подъёма» для конкретного перехода (не единый срок — см. шаг 4) И реальный паттерн следующей категории уже наблюдается в A_scope? Таблица также перечисляет качественные условия перехода (размер и устойчивость круга, не только срок) — сверяй их, а не только дату
   - Ступень мастерства (`PD.FORM.080`) калибрует только объём поддержки и сопровождения — она НЕ открывает и не закрывает эту готовность
   - Выведи `ready_for_next_document: true/false` с кратким основанием

7. **Не останавливайся и не выводи результаты отдельным ответом.** Измерения (V_scope, A_scope, D_scope, качественный статус, `ready_for_next_document`) — вход шага 05b этого же этапа «Калибр»: прочитай `05b-recommendation.md` в этом же ходе; пилот увидит измерения вместе с рекомендацией и решит один раз.
