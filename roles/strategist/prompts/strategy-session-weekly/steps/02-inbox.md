# Step 02: Разбор входящих

## ВДВ

| | |
|---|---|
| **Вход** | Раздел «Разбор входящих» черновика плана недели (если есть) или: `inbox/fleeting-notes.md` + свежие файлы за неделю + отчёты извлечения на решении + QA-отчёт бота |
| **Действие** | Классифицировать каждый элемент: в план / в неудовлетворённость / capture / удалить / отложить |
| **Выход** | Решения по inbox, обновлённый fleeting-notes.md |

## Инструкция для Claude

1. **Прочитать источники** (если черновик плана недели содержит раздел «Разбор входящих» — начни с его перечня, он собран по этим же источникам):
   - `inbox/fleeting-notes.md`
   - Все файлы из `inbox/` (кроме .DS_Store и .docx)
   - QA-отчёт бота: `DS-agent-workspace/scheduler/feedback-triage/` (последний по дате)

2. **По каждому элементу** пилот решает:
   - **В план недели** → добавить в candidate pool (шаг 06a)
   - **В неудовлетворённость** → передать формулировку этапу «Неудовлетворённости» (шаг 03); в `docs/Dissatisfactions.md` не писать до решения пилота там. В короткой сессии этого этапа нет — запиши в план недели строкой «Кандидат в неудовлетворённости на полную сессию: …»
   - **Capture в Pack** → зафиксировать через `/ke` или записать в Pack
   - **Удалить** → применить сразу
   - **Отложить** → пометить `🔄` с датой пересмотра

3. **Недельная агрегация Inbox Triage:**
   - Собери все `🔄` заметки (идеи, висящие >7 дней)
   - Собери непринятые предложения из прошлых Note-Review
   - Сформируй 3 корзины: ✅ Архив / 📌 Предложения в РП / ❓ На решение

4. **Вопрос пилоту:**
   > «Продолжить к этапу {N} «{название}» / скорректировать / пропустить?» — следующий этап, номер и название из таблицы «Этапы сессии» для выбранного варианта (полная или короткая).
