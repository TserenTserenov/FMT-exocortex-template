# Step 06c: План недели — доводка

## ВДВ

| | |
|---|---|
| **Вход** | Бюджет + ТОС (шаг 06b), список кандидатов |
| **Действие** | Сверка РП↔НЭП, финализация таблицы WeekPlan |
| **Выход** | Черновик WeekPlan: существующие РП и список новых кандидатов для утверждения |

## Инструкция для Claude

1. **Сверка РП↔НЭП↔гипотеза** — для каждого выбранного РП назови источник:
   - `R{N}` — приоритет месяца
   - `S-НЭП-X` — неудовлетворённость
   - `carry` — carry-over
   - РП без источника — сигнал «зачем это делаем?», требует решения сейчас
   - Если РП проверяет или меняет главную гипотезу месяца, добавь `H-NNN`.
     Если такой связи нет, явно укажи, что РП поддерживает текущую норму, а не
     проверяет стратегическую ставку.

2. **Финализация таблицы:**
   Обнови таблицу существующих РП в WeekPlan с колонками:
   `🚦 / # / РП / Бюджет / Источник / Статус / Дедлайн / Репо`
   Новых кандидатов покажи отдельным списком с источником, бюджетом и критерием готовности, без окончательного номера. До шага 08 план остаётся `draft`: строка кандидата не заменяет регистрацию. В шаге 08 `/wp-new` добавит строки выбранных новых РП; затем дополни именно их согласованными полями, без дублей. Общий порядок — раздел «Регистрация РП перед утверждением» скилла `strategy-session`.

3. **Вопрос пилоту (единственная остановка этапа «План недели: бюджет и доводка»):** покажи одним ответом бюджет и время, ограничение недели (ТОС), список «не берём» со сроками пересмотра и таблицу РП с источниками.
   > «Продолжить к этапу {N} «{название}» / скорректировать / пропустить?» — следующий этап, номер и название из таблицы «Этапы сессии» для выбранного варианта (полная или короткая).
