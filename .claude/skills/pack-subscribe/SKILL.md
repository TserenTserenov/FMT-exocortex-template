# /pack-subscribe — подписка на чужой пак

Запрос: $ARGUMENTS

> **Статус: экспериментальный.** Зеркальный скилл — `/pack-new` (создание СВОЕГО пака). Подписка
> не создаёт пак, а подключает чужой только для чтения.

## When to use

- Пользователь хочет увидеть, какие базы знаний других авторов можно подключить («какие паки есть»).
- Пользователь просит подключить конкретный пак («подключи пак PACK-…», `/pack-subscribe PACK-…`).
- Пользователь просит отключить подписку («отключи пак PACK-…»).

Не для создания своего пака (это `/pack-new`) и не для правки чужого: правки идут в свой пак.

## Обещание (контракт)

**Вход:** имя пака из каталога (или пусто — показать витрину).
**Выход:** пак склонирован в `${IWE_WORKSPACE:-$HOME/IWE}/<имя>` только для чтения, внесён в
ваш файл расширения `extensions/protocol-open.after.pack-subscriptions.md` (список, автообновление,
область поиска), виден поиску по пакам, отмечен в реестре репозиториев (если он есть); пользователю
показана памятка подписчика.

**Инвариант (БЛОКИРУЮЩИЙ):** подписанный пак никогда не редактируется локально. Единственные
операции — `git pull` (обновления) и чтение. Адаптация знания = копия в СВОЙ пак с атрибуцией
(пак, файл, коммит или дата); оригинал не трогается. Ошибку в чужом паке — сообщить автору
(замечание в его репозитории), не исправлять.

## Где что хранится

| Что | Где | Кто владеет |
|---|---|---|
| Поставляемый каталог | `.claude/skills/pack-subscribe/pack-catalog.yaml` | платформа (обновляется `update.sh`) |
| Свой каталог (по желанию) | `extensions/pack-catalog.yaml` или ключ `pack_catalog_url` в `params.yaml` | пользователь |
| Список подписок, автообновление, `default_scope` | `extensions/protocol-open.after.pack-subscriptions.md` | пользователь |
| Копия пака | `${IWE_WORKSPACE:-$HOME/IWE}/<имя>` | автор пака (локально — только чтение) |

Список подписок живёт в файле расширения, а не в `CLAUDE.md`: `CLAUDE.md` — файл платформы
(обновление шаблона перезаписывает его целиком, кроме блока USER-SPACE, который пользователь ведёт
сам), а пользовательские правила по Extensions Gate идут в `extensions/` — его обновление не
трогает и копирует в резервную копию. Протокол открытия сессии загружает этот файл через точку расширения
`protocol-open after` (`.claude/scripts/load-extensions.sh protocol-open after`).

## Algorithm

```bash
W="${IWE_WORKSPACE:-$HOME/IWE}"
SKILL="$W/.claude/skills/pack-subscribe"
EXT="$W/extensions/protocol-open.after.pack-subscriptions.md"
# catalog.py needs PyYAML; the resolver finds a python3 that has it.
PY3="$(bash "$W/.claude/lib/find-python3.sh")" || { echo "нет python3 с PyYAML — см. сообщение выше" >&2; }
```

Если резолвер отказал — сказать пользователю его сообщение (как установить зависимость) и СТОП.

### 1. Каталог и витрина

Каталог собирает один разборщик: `"$PY3" "$SKILL/catalog.py" list --workspace "$W"`.
Источники по убыванию приоритета (запись с тем же именем из более высокого источника заменяет
нижнюю):

1. `extensions/pack-catalog.yaml` — свой каталог пользователя.
2. `pack_catalog_url` в `params.yaml` — адрес `https://…` или путь к файлу.
3. Поставляемый каталог рядом со скиллом.

Записи с `offered: internal-only` в витрину не попадают никогда — даже если такая строка пришла из
чужого каталога пользователя. Записи с ошибками схемы (нет полей, адрес не `https://`, имя не
`PACK-…`) разборщик пропускает и пишет причину; проверить свой каталог целиком:
`"$PY3" "$SKILL/catalog.py" validate <файл>`.

Без аргумента → показать витрину таблицей: имя, область, описание, доступ (`open` — открыт всем,
`by-subscription` — нужно право чтения от автора), для кого, подключён ли уже. СТОП — ждать выбора.

### 2. Проверка перед подключением

`"$PY3" "$SKILL/catalog.py" show <имя> --workspace "$W"` — код выхода решает:

- **3** — запись помечена `internal-only` → **«<имя> не выдаётся по подписке (внутренний пак)»**,
  СТОП. Явный запрос по точному имени это не обходит.
- **4** — пака нет в каталоге → «Пака нет в каталоге», показать витрину.
- **0** — JSON записи: дальше берутся `url`, `owner`, `access`, а `connected` говорит, есть ли копия.

Затем:

- Папка `"$W/<имя>"` уже есть:
  - это подписка (`git -C "$W/<имя>" config --get iwe.subscription.owner` не пусто) → «Уже
    подключён», предложить обновить (`git -C "$W/<имя>" pull --ff-only`). СТОП.
  - это НЕ подписка (свой репозиторий или посторонняя папка с тем же именем) → «В рабочей папке
    уже есть <имя>, подписка не выполнена — переименуйте свою папку или выберите другой пак». СТОП.
- Проверить доступ: `GIT_TERMINAL_PROMPT=0 git ls-remote -- "<url>" HEAD >/dev/null 2>&1`.
  Отказ:
  - `access: by-subscription` → **«Нет доступа к <имя>: запросите право чтения у автора
    (<owner>)»**, СТОП. Это штатное ограничение для тех, у кого нет подписки, не ошибка.
  - `access: open` → «Репозиторий <имя> сейчас недоступен (сеть или адрес) — попробуйте позже», СТОП.

### 3. Подключение (цель: не дольше минуты; замерить и сообщить время)

```bash
START=$(date +%s)
NAME="<имя>"; URL="<url>"; OWNER="<owner>"
git clone --quiet -- "$URL" "$W/${NAME}"
git -C "$W/${NAME}" config --local iwe.subscription.owner "${OWNER}"
git -C "$W/${NAME}" config --local iwe.subscription.since "$(date +%F)"
# Local read-only guard: refuse commits and pushes in the subscribed copy.
HOOKS="$W/${NAME}/.git/iwe-readonly-hooks"
mkdir -p "$HOOKS"
for h in pre-commit pre-merge-commit pre-push; do
  printf '#!/bin/sh\necho "%s: подписанный пак только для чтения. Свои правки - в свой пак с пометкой источника." >&2\nexit 1\n' "${NAME}" > "$HOOKS/$h"
  chmod +x "$HOOKS/$h"
done
git -C "$W/${NAME}" config --local core.hooksPath .git/iwe-readonly-hooks
```

Затем две пометки:

1. **Файл расширения** — создать при первой подписке из шаблона, дальше пополнять список:

   ```bash
   [ -f "$EXT" ] || cp "$SKILL/templates/subscriptions-extension.md" "$EXT"
   grep -q "^- \`${NAME}\`" "$EXT" || printf -- '- `%s` — автор %s, подключён %s\n' "${NAME}" "${OWNER}" "$(date +%F)" >> "$EXT"
   ```

   Файл содержит правила только-для-чтения, команду автообновления в начале сессии и настройку
   `default_scope` (`all-connected` по умолчанию / `own-only`). Просьбу «сделай по умолчанию
   own-only» (или наоборот) выполнять правкой строки `default_scope:` в этом файле.

2. **Реестр репозиториев пользователя** — если в установке есть реестр (`REPOSITORY-REGISTRY.md`
   или аналог) → строка: имя, класс «Pack (подписка, только чтение)», автор, дата. Реестра нет →
   пропустить молча.

**Область поиска.** Поиск по пакам находит локальные паки по шаблону `PACK-*` в корне рабочей папки
(например, `/fpf`, `/find-method`), поэтому подключённый пак виден ему сразу. При
`default_scope: own-only` подписанные паки (строки списка в файле расширения) из поиска исключать,
пока пользователь не попросит иначе. В ответе помечать, из какого пака взято знание.

### 4. Памятка

Показать пользователю `templates/subscriber-memo.md` целиком (одна страница) и предложить сохранить
копию в его рабочую папку.

### 5. Отчёт

Одной строкой: что подключено, сколько секунд заняло (`$(( $(date +%s) - START ))`), как искать, как
обновлять. Дольше минуты — сказать об этом прямо, с причиной (сеть, размер репозитория).

## Отключение («отключи пак <имя>»)

1. Убедиться, что это подписка (`iwe.subscription.owner` задан); иначе отказать — свой репозиторий
   этот скилл не удаляет.
2. Спросить подтверждение: удаление копии необратимо (подключить можно снова). Если
   `git -C "$W/<имя>" status --porcelain` не пуст — назвать файлы: это локальные правки, которых по
   инварианту быть не должно; предложить сначала перенести нужное в свой пак.
3. После «да»: `rm -rf "$W/<имя>"`, убрать строку из файла расширения
   (`grep -v "^- \`<имя>\`" "$EXT" > "$EXT.tmp" && mv "$EXT.tmp" "$EXT"`) и из реестра, если она там есть.

## Ограничения версии 0.3 (экспериментальная)

- Список и настройка поиска загружаются в начале рабочей сессии, которая проходит протокол
  открытия. Короткий вопрос без открытия сессии их не загружает: пак остаётся видимым поиску
  (`PACK-*`), а настройку `own-only` агент в такой беседе не знает; защита от правок в копии
  (отказ коммита) действует всегда.
- Автообновление — инструкция агенту в начале сессии, не плановое задание: день без сессий —
  без обновления.
- Работает только в локальной среде (VS Code и терминал): в браузерном чате и в боте подписки нет.
