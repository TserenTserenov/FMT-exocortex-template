# /peer-fanout — раздача независимых подзадач нескольким агентам

Задача: $ARGUMENTS

## Когда применять

Задача распадается на несколько подзадач, которые **не зависят друг от друга**: ответ одной не нужен для другой (например, оценить три варианта, разобрать три документа, найти риски с трёх сторон). Все подзадачи уходят агентам одновременно, общее время ≈ время самой долгой, а не сумма.

Не применять:
- нужен разговор с обсуждением и согласием → `/peer-conversation`;
- шаги зависят друг от друга (выход одного — вход другого) → делать по очереди; такие схемы (конвейер, надзиратель, рой) запланированы на следующие выпуски;
- подзадаче нужны файлы рабочей папки: агент получает только текст подзадачи, без доступа к файлам.

## Стоимость — предупредить до запуска

Каждая подзадача — отдельный вызов агента, он тратит токены подписки (или ключа) этого агента. Пять подзадач — пять вызовов. Перед запуском назвать человеку число подзадач и агентов; больше пяти подзадач за раз — только после его согласия.

## Шаг 1. Разложить на подзадачи

Каждая подзадача — **одна строка**, самодостаточная: всё нужное для ответа — в её тексте (агент не видит этот разговор и файлы). Без символа табуляции и переносов строки внутри.

Файл подзадач — по строке на подзадачу, три колонки через табуляцию: `id<TAB>агент<TAB>текст подзадачи`.
- `id` — латиница, цифры, `.`, `_`, `-`; уникален; станет именем файла ответа;
- агент — `claude`, `codex`, `kimi` или `hermes`; если установлен только Claude Code — всем `claude`;
- строки, начинающиеся с `#`, и пустые строки пропускаются.

Файл писать через `printf` с `\t`, чтобы табуляция была настоящей:

```bash
FANOUT_DIR=$(mktemp -d "${TMPDIR:-/tmp}/fanout.XXXXXX")
printf '%s\t%s\t%s\n' \
  risk-a claude "Назови главный риск варианта А: ... (одним абзацем)" \
  risk-b claude "Назови главный риск варианта Б: ... (одним абзацем)" \
  > "$FANOUT_DIR/tasks.tsv"
```

## Шаг 2. Запустить

```bash
FANOUT="${IWE_SCRIPTS:-${IWE_WORKSPACE:-$HOME/IWE}/scripts}/peer-fanout.sh"
[ -f "$FANOUT" ] || FANOUT="${IWE_TEMPLATE:-${IWE_WORKSPACE:-$HOME/IWE}/FMT-exocortex-template}/scripts/peer-fanout.sh"
bash "$FANOUT" --tasks "$FANOUT_DIR/tasks.tsv" --out-dir "$FANOUT_DIR/out"
```

- Перед запуском скрипт проверяет весь файл и наличие программ агентов; при ошибке ни один агент не вызывается.
- Сторож на каждую подзадачу — 600 секунд (`IWE_FANOUT_TIMEOUT_SEC`, от 1 до 3600); по истечении снимает и агента, и запущенную им программу.
- `--peer claude,codex` — необязательная проверка: разрешённые агенты, всё остальное отклоняется.
- Долгий запуск (больше трёх минут) — запускать в фоне и сообщить человеку, что идёт и сколько подзадач.

## Шаг 3. Прочитать итог

Скрипт всегда печатает сводку: строку на подзадачу (статус, размер ответа, время) и последнюю строку `ok=N total=M out_dir=... wall_s=...`.

| Код выхода | Значение |
|---|---|
| 0 | все подзадачи выполнены |
| 2 | часть не выполнена (`error:<код>`, `error:empty`, `timeout`, прерывание) — готовые ответы целы |
| 1 | файл подзадач или окружение не прошли проверку — никто не вызывался |

Ответы — `out/<id>.md`, ошибки агента — `out/<id>.err`. Готовые ответы в папке скрипт не перезаписывает: повторный запуск — в новую папку.

## Шаг 4. Свести в общий отчёт

Прочитать все `out/<id>.md` и дать человеку один отчёт: по каждой подзадаче — короткий итог со ссылкой на файл ответа; затем общий вывод (где ответы сходятся, где расходятся, что из этого следует). Невыполненные подзадачи назвать отдельно с причиной из сводки; повторять их — только с согласия человека (это снова расход токенов).

## Проверка перед выпуском

Схема входит в выпуск только после живого прогона не автором шаблона на чистой установке. Пошаговая инструкция для проверяющего — `docs/PEER-FANOUT-LIVE-CHECK.md`.
