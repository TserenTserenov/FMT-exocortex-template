# Персональное руководство: как оно собирается

## Текущее состояние (2026-07-29)

Сборка руководства — облачная возможность платформы: она читает данные пилота из баз платформы, обращается к LLM по ключу платформы и публикует результат в GitHub-репозиторий руководства. Всё это происходит **на сервере платформы автоматически по расписанию** — каждое утро появляется новый урок, по понедельникам пересобирается полный комплект.

Ручной пересбор из чата («пересобери сейчас») пока недоступен: серверный MCP-инструмент для этого ещё не опубликован. Когда он выйдет, этот скилл начнёт вызывать его напрямую — следите за обновлениями шаблона.

## When to use

Пилот просит «пересобери руководство», «обнови мой план», «собери руководство на сегодня» — либо спрашивает, почему руководства за сегодня нет.

## Algorithm

## Шаг 0. Проверить предусловие (setup завершён)

Вызови `personal_search(source: "DS-personal-guide", path: "README.md")`.

> #503: раньше здесь проверялся платформенный путь `.claude/skills/...` —
> он живёт в шаблоне (слой L1) и в пользовательский репозиторий DS-personal-guide
> не копируется никогда, проверка гарантированно возвращала пусто и блокировала
> все следующие шаги. Реальный признак завершённого bootstrap — README.md:
> его создаёт сам bootstrap при создании репозитория (notes-структура
> Gateway: inbox/, docs/, README.md), т.е. он существует ДО первого рендера.

Если файл **не найден** → сообщить пилоту:
```
Скиллы не установлены или установка не завершена.
Запусти /personal-guide-start для первичной настройки.
```
Стоп (не переходить к Шагу 1).

## Шаг 1. Определить дату

`date` = аргумент скилла если передан (формат YYYY-MM-DD), иначе сегодня.

Определи ISO-неделю выбранной даты в формате `YYYY-Www`, используя год ISO-недели (он может отличаться от календарного года около Нового года).

## Шаг 2. Проверить, доехало ли руководство

Проверь в репо `DS-personal-guide` пилота наличие `guide/<ISO-неделя>.md` (недельный материал), `guide/<date>.md` (дневной материал) и `panel/<date>.md` (табло). Первые два пути — кандидаты для разных режимов: не требуй наличия обоих и не определяй режим только по дню недели.

Если доступен `guide.json`, сверяй явно указанные пути в `sections.weekly` и `days` с выбранным периодом. Подтверждай режим только при явной ссылке на соответствующий материал; иначе укажи, что режим не подтверждён. Оглавление не является маркером полноты: не требуй несуществующих полей `mode`, `complete` или ссылки на табло.

**Сообщи результат отдельно для каждого проверенного пути:**
```
Проверены файлы за <date>:
<путь учебного материала> — найден / отсутствует.
panel/<date>.md — найден / отсутствует.
Режим: недельный / дневной (подтверждён оглавлением) / не подтверждён.
```

Наличие файлов подтверждает их доступность, но не новый успешный запуск генератора или актуальность содержимого. Не объявляй комплект полным по одному файлу или одному оглавлению.

**Если для выбранного периода не найден ни один учебный материал или отсутствует табло:**
```
Руководство собирается на сервере платформы автоматически (утром по расписанию).
Ручной пересбор из чата пока недоступен — серверный инструмент в разработке.
Если руководства нет к середине дня — сообщи в поддержку платформы.
```
