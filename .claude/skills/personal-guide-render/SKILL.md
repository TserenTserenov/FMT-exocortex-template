# Проверка персонального руководства

## When to use

Пользователь просит пересобрать руководство, обновить план или проверить,
почему материалы не появились. Скилл выполняет чтение; сам по себе он не запускает
серверную генерацию. Вызов из `/personal-guide-start` имеет те же условия.

## Доступность генерации

Генерацию выполняет сервер платформы. Ручной MCP-инструмент пересборки пока не
опубликован. Не вызывать вымышленный `render_personal_guide`, не генерировать
личные материалы вместо сервера и не обещать срок по описанию старого расписания.
Только ответ действующего сервиса о конкретном задании подтверждает его запуск.

## Algorithm

## Шаг 0. Проверить доступ к источнику

Вызови `github_status`, проверь подключение `DS-personal-guide` и отсутствие
`github_owner_mismatch: true`. Несовпадение аккаунта или отказ в доступе — остановить
чтение и предложить переподключение. Источник не подключён — предложить подключить
существующий репозиторий; не считать отсутствие в списке доказательством, что его
нужно создать заново.

Прочитай README актуальным вызовом:
`personal_get_document(source="DS-personal-guide", filename="README.md", include_sha=true)`.
При больших ответах пройти все страницы по контракту инструмента. Если путь
подтверждённо отсутствует, сообщить о незавершённой подготовке и предложить
`/personal-guide-start`. Ошибка чтения не равна отсутствию файла. Пустой результат
`personal_search` может означать задержку индекса — прежде чем заявлять отсутствие,
проверь чтение из GitHub. Если оно недоступно, результат «не удалось проверить».

README — признак доступного репозитория, не полного руководства. Скиллы L1
доставляются из шаблона через IWE или общий MCP-загрузчик; их наличие внутри
`DS-personal-guide/.claude/skills/` не проверять и не требовать (#503, #1263).
Приватность репозитория этот скилл по одному `github_status` не устанавливает;
не выдавать результат чтения за завершённую проверку настройки.

## Шаг 1. Определить период

`date` = аргумент YYYY-MM-DD, иначе сегодня в часовом поясе пользователя.
Определи ISO-неделю `YYYY-Www` с годом ISO-недели: около Нового года он может
отличаться от календарного года. Не выбирать режим только по дню недели.

## Шаг 2. Проверить материалы и табло

Через `personal_get_document` с `include_sha=true` прочитай известные пути:

- `guide/<ISO-неделя>.md` — недельный материал;
- `guide/<date>.md` — дневной материал;
- `panel/<date>.md` — табло.

Для материала достаточно дневного **или** недельного файла за выбранный период;
табло проверяется отдельно и также требуется. Пустой или нечитаемый файл не
подтверждает доступность материала. Сохранить различие «не найден» и «чтение
не удалось». Если актуальное чтение недоступно, индексированный результат можно
назвать только наблюдением индекса, не доказательством текущего состояния GitHub.

Если доступен `guide.json`, сверь явно указанные пути в `sections.weekly` и `days`
с выбранным периодом. Режим подтверждай только явной ссылкой на соответствующий
материал. Не требуй одновременно оба режима, несуществующие поля `mode`/`complete`
или ссылку на табло в оглавлении. Оглавление не доказывает полноту комплекта.

## Шаг 3. Сообщить результат и следующий шаг

Сообщи отдельно для каждого проверенного пути:

```text
Проверены материалы за <date>:
<путь материала> — доступен / отсутствует / не удалось проверить.
panel/<date>.md — доступен / отсутствует / не удалось проверить.
Режим: недельный / дневной (подтверждён оглавлением) / не подтверждён.
Генерация: запуск подтверждён / ошибка подтверждена / запуск не подтверждён.
```

Наличие файлов подтверждает доступность, но не новую генерацию или содержательную
актуальность. `bootstrap_completed`, ответ загрузчика или отсутствие ошибки
у скилла не подтверждают полный комплект. Повторное чтение готового комплекта
не требует нового задания генератора.

Если материала за период или табло нет, не обещай автоматическое появление
«утром» и не объявляй «ожидает генерации» без подтверждённого задания. Укажи
недостающий результат. При доступных диагностических инструментах проверь
существующий серверный процесс; иначе предложи обратиться в поддержку с датой,
путями и ошибкой чтения, без передачи содержимого личных файлов. Настройку
репозитория из-за этого не повторять и историю не перезаписывать.
