# /onboarding — лёгкий онбординг

Задача человека (если передана): $ARGUMENTS

Этот навык — тонкая привязка к среде шаблона IWE. **Сценарий разговора в навыке не пишется.** Он целиком в одном файле, единственной редакции, которую так же читает инструкция Open MCP.

## When to use

- Человек пишет `/onboarding`.
- Новый человек спрашивает «с чего начать?» или «что ты умеешь?».
- Человек просит разобрать свою задачу методом.

Не для участника, вошедшего аккаунтом МИМ: у него полный онбординг (DP.SC.170).

## Algorithm

### Шаг 1. Прочитай канонический текст целиком

Текст лежит в копии шаблона IWE, в `docs/onboarding/light-onboarding.md`. Найди его по порядку, до первого найденного:

1. `$IWE_TEMPLATE/docs/onboarding/light-onboarding.md`, если переменная окружения `IWE_TEMPLATE` задана;
2. `<рабочая папка IWE>/FMT-exocortex-template/docs/onboarding/light-onboarding.md` (рабочая папка — та, где лежит `CLAUDE.md`);
3. поиск по имени: `find <рабочая папка IWE> -maxdepth 4 -path '*docs/onboarding/light-onboarding.md' -not -path '*/archive/*'`.

Прочитай файл полностью, не по фрагментам, и веди разговор строго по нему: правила §1, развилка §2, разделы §3–§11.

Файл не найден ни одним способом → скажи человеку, что сценарий онбординга в этой установке недоступен, и предложи обновить шаблон (`/iwe-update`). Не восстанавливай сценарий по памяти.

### Шаг 2. Что в этой среде значит «найди метод в библиотеке методов»

Библиотека методов в шаблоне — **локальные копии** в рабочей папке IWE (`$IWE_WORKSPACE`, по умолчанию папка, где лежит `CLAUDE.md`):

| Порядок | Где искать | Что это |
|---|---|---|
| 1 | `PACK-*/pack/` | паки — методы предметных областей; в чистой установке их может не быть |
| 2 | `FPF/`: сначала `FPF/FPF-LIBRARY-REFERENCE.md` (устройство библиотеки) и `FPF/USING-FPF.md` (как искать и читать), затем наборы `FPF/DPFs/` (решения, цели, объяснение, инженерия, мышление) и `FPF/FPF-Spec.md` | первые принципы и общие методы мышления и работы; текст на английском — ищи по английским словам |
| 3 | `SPF/` (`docs/`, `spec/`, `process/`) | форма и порядок описания знаний |

Как искать:

- Поиск по смыслу задачи, на русском и на английском: `rg -n -i -C 2 --no-ignore -g '*.md' -- '<термин>' <папка>`; нет `rg` → `grep -rn -i --include='*.md' -- '<термин>' <папка>`.
- Совпадение в оглавлении или справочнике — ещё не метод. Прочитай найденный раздел целиком, прежде чем объяснять метод человеку.
- Повторный поиск (текст, §7 шаг 2) — другие слова: синонимы, английское название, уровень обобщённее.
- «Место в библиотеке» для объяснения и квитанции — название раздела без внутреннего кода (номер паттерна не называй) и путь к файлу; версия — `git -C <папка> log -1 --format='%h %ad' --date=short`, если папка под git.
- Нет ни одной из папок → это отказ 1 текста (библиотека недоступна). Скажи человеку, как её получить: копии FPF и SPF скачиваются при установке шаблона, если на компьютере есть вход в GitHub (`gh auth login`); вручную — `gh repo clone ailev/FPF <рабочая папка IWE>/FPF -- --depth=1`.

### Шаг 3. Границы привязки

- **Не вызывай инструменты MCP с подпиской** (поиск по базе знаний, профиль, онбординг аккаунта, диагностика, руководство) — даже если подключение есть. Лёгкий онбординг их не использует. Человек сам спросил про аккаунт → §9 текста.
- **Не перепоручай поиск навыку `/fpf`**: он сначала обращается к MCP с подпиской. Ищи по шагу 2.
- Отметки §11 текста держи в разговоре. Ничего не записывай в файлы человека, пока он сам об этом не попросит.
- Квитанцию §10 покажи в чате; сохранить её в файл — только по просьбе человека и туда, куда он скажет.
