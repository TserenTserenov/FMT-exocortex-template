# Stop List: When to Interrupt a Work Project — Full Specification

> Hot trigger: `${IWE_GOVERNANCE_REPO:-DS-strategy}/CLAUDE.md` § Stop list (compact table). This file contains the full definitions (WP-450 Phase1).

The Strategist must check stop criteria at every Strategy Session (Step 2, Review). If at least one criterion is triggered — raise the question of interrupting or reformulating the work project.

| Criterion | Signal | Action |
|----------|--------|----------|
| **Budget exhausted** | More than 150% of budget spent with no visible Progress | STOP. Reassess: incorrect estimate or incorrect approach? |
| **Blocker >2 weeks** | Work project is blocked by an external dependency that is not moving | Freeze (status: blocked). Redirect budget to another work project |
| **Hypothesis disproved** | The original assumption turned out to be incorrect | Close or reformulate. Do not carry a dead work project forward |
| **Priority dropped** | The target outcome the work project is tied to is no longer relevant | Move to Backlog or close |
| **Result achieved another way** | Another work project or an external event resolved the problem | Close with the note "resolved externally" |
| **Caliber gap** | The work project requires a caliber 2+ levels above the current one, with no growth plan in place | Decompose into manageable parts or find a collaborator |

**Anti-pattern:** "I have already invested so much, it feels wasteful to stop" (sunk cost fallacy). The stop list exists precisely to counter this — decisions are based on future value, not past costs.
