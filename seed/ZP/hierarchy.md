# Principles Hierarchy

> A map of all principle levels in the ecosystem.

---

## Map

```
Level 0: Zeroth Principles
│   Trans-disciplinary meta-constraints
│   Framework: none (too fundamental)
│   Repo: ZP (this repo)
│
├── discipline ↓
│
Level 1: First Principles
│   Foundational bases of disciplines
│   Framework: FPF (principles + framework in one bundle)
│   Repo: FPF
│
├── constrain ↓
│
Level 2: Second Principles
│   Domain-level principles
│   Framework: SPF (form and process only, no principles themselves)
│   Principles: Pack (each Pack = a set of second principles for a specific domain)
│   Repo: SPF + PACK-*
│
├── define ↓
│
Level 3: Third Principles
│   Situational and project-level principles
│   Frameworks: S2R and others (multiple possible frameworks)
│   Principles: DS (specific projects, bots, courses)
│   Repo: DS-*
```

## What exists at each level

| Level | Principles (content) | Framework (form) | Rationale |
|-------|----------------------|------------------|-----------|
| 0 | Zeroth (ZP.1–ZP.6) | None | Too fundamental — 6 principles, no formalization needed |
| 1 | FPF (holons, BC, trust calculus, Γ-algebra) | FPF (calculi, inference rules) | Heavy — useless without machinery, so bundled |
| 2 | Pack (domain: DP, MIM, PD, ECO...) | SPF (11-step process, templates) | Many domains — a single formalization standard is required |
| 3 | DS (specific systems) | S2R and others | Many project types — different formats are required |

## Synonyms

| Ecosystem term | Principle level | Example |
|----------------|-----------------|---------|
| **Pack** | = second principles | PACK-digital-platform, PACK-MIM |
| **DS** | = third principles | DS-aist-bot, DS-strategist-agent |
| **FPF** | = first principles + framework | FPF (bundle) |
| **SPF** | = framework for second principles | SPF (form only) |
| **S2R** | = one of the frameworks for third principles | FMT-s2r |

## Fallback Chain

```
DS (Level 3) → Pack (Level 2) → Base.Principles (SPF → FPF → ZP)
```

## Skills in the hierarchy

Skills — automated execution procedures — exist at the **DS (Level 3)** level. They are generated by principles, not a replacement for them.

```
ZP    → HOW TO THINK        (cognitive infrastructure, cross-domain transfer)
FPF   → HOW TO DESCRIBE     (correctness, strict distinctions)
Pack  → WHAT TO KNOW in a domain (source of truth, domain language)
DS    → WHAT TO DO          (skills, programs, tools)
```

**Why skills are not enough:**
1. A Skill is procedural — it answers "how to do THIS", not "which procedure to choose"
2. Skills do not transfer — a surgeon's skill is useless in management
3. A "bucket of skills" ≠ an integrated capability (FPF B.2.4)
4. Skills do not generate new skills — principles do
